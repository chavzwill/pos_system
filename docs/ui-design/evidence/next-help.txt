
Usage:
  12ui next <run-dir|run-id> [--wait] [--timeout-ms <ms>] [--json]

Read durable status and report the one useful command to run next.

Behavior:
  - Recognizes local Codex conversion and project-apply runs, draft and branch directories, hosted
    run IDs, conversion IDs, and journal-backed workspaces.
  - A bare read never starts, retries, or resumes work. Human status is the default; --json writes
    the machine record to stdout and suppresses the human progress stream.
  - For local runs, --wait only observes recorded state; it never dispatches. For hosted drafts,
    --wait repairs only recorded draft slots that are still pending, dispatching exactly those
    never-started slots before polling and downloading.
  - --wait polls with heartbeats until terminal status. It has no hidden deadline; use --timeout-ms
    only for a deadline supplied by the user or request, never as an invented polling interval.
  - Replaces the retired per-subsystem status commands.
