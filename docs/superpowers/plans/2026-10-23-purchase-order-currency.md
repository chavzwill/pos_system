# Purchase-order currency conversion

User-authorized scope: add currency conversion and options to PO creation. Reuse managed procurement FX, no paid rate feeds or deployment. Existing PO/receipt/AP amounts remain in procurement base currency; supplier-entered currency costs and totals are preserved separately. The current procurement base is the authority (normally JMD), not the separate retail currency display setting.

Implementation decision: immutable FX snapshot with rate direction `1 supplier currency = rate base currency`, source/date/actor evidence. Select a valid managed rate, or allow authenticated purchasing approvers a documented one-order rate. Convert entered unit cost before UOM normalization, then save original currency line economics plus normalized base amounts atomically in the PO transaction. Reject missing/expired/stale managed rates and invalid financial inputs. Copy documents with supplier currency and source prices, obtaining fresh rates rather than copying approvals. Handle PR-to-PO conversion without treating foreign costs as local. New-order entry in both interfaces and PO review/documents display explicit currency labels and both totals. Inventory receiving and AP continue consuming normalized base costs and are never triggered by creating a PO.

Validation: integer-decimal conversion rules; real database tests for base/foreign/managed/manual rates, UOM, stale/missing rates, permissions, rollback and snapshot immutability; browser desktop/phone creation and copy; existing receiving, invoice and sales regressions; full source checks. Publish a draft PR with local evidence and skip unnecessary Actions; no merge/deployment without continuation.

Frozen PO valuations reject catalog-line appends with guidance to copy a new draft. Historical POs retain the existing path. Approved PR conversion preserves its original currency; changing a currency code cannot relabel existing quoted costs. Currency controls update their own fields without replacing delivery or UOM nodes.

Verification: 8 currency runtime/browser scenarios, 11 existing receiving/invoice regression scenarios, and 15 focused Node tests pass. Full source-check sequence passed after preserving approval-brief placement and rerunning the remaining contracts; client syntax and new backend modules checked explicitly.
